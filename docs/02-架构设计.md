## 2. RAG Pipeline（核心）

### 2.1 Ingestion 流程（文档入库）

```
上传文件
   │
   ▼
保存原文件 (local / MinIO)
   │
   ▼
创建 document 记录 (status=pending)
   │
   ▼
异步 Worker 启动
   │
   ├─► 解析：PDF → 纯文本 / MD → 纯文本
   │
   ├─► 切块 (Chunking)
   │     chunk_size=500, overlap=50, 按段落优先
   │
   ├─► Embedding：batch 调用 API → 向量列表
   │
   └─► 写入 chunk 表 + pgvector 索引
         document.status = ready
```

### 2.2 Query 流程（问答）

```
用户提问 + knowledge_base_id
   │
   ▼
问题 Embedding
   │
   ▼
向量检索 Top-K (cosine similarity, K=5~8)
   │  可选：混合检索 + Rerank
   ▼
拼装 Prompt：
   system: 仅根据上下文回答，不知道就说不知道
   context: [1] 片段A  [2] 片段B ...
   user: 问题
   │
   ▼
调用 LLM（流式 SSE）
   │
   ▼
保存 message + citations
   │
   ▼
返回：answer + sources[{chunk_id, doc_title, excerpt, score}]
```

### 2.3 切块策略（面试常问）

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| chunk_size | 400–600 字符 | 中文约 200–300 字 |
| chunk_overlap | 50–100 字符 | 避免语义在边界断裂 |
| 分隔符 | `\n\n` > `\n` > 。 | 优先按段落切 |
| metadata | doc_id, page, index | 用于引用展示 |

**进阶**：Semantic Chunking（按 embedding 相似度合并）— Phase 4 可选。

## 3. 模块划分

### 3.1 Backend 包结构

```
app/
├── main.py                 # FastAPI 入口、CORS、路由挂载
├── core/
│   ├── config.py           # 环境变量 pydantic-settings
│   ├── security.py         # JWT 签发/校验、密码 hash
│   └── deps.py             # 依赖注入：get_db, get_current_user
├── models/                 # SQLAlchemy ORM
├── schemas/                # Pydantic 请求/响应
├── api/v1/
│   ├── auth.py
│   ├── knowledge_bases.py
│   ├── documents.py
│   └── chat.py
├── services/
│   ├── auth_service.py
│   ├── kb_service.py
│   ├── document_service.py
│   └── rag/
│       ├── chunker.py
│       ├── embedder.py
│       ├── retriever.py
│       ├── generator.py
│       └── pipeline.py     # ingest + query 编排
└── workers/
    └── ingest_worker.py    # 后台解析任务
```

### 3.2 关键类职责

| 类/模块 | 职责 |
|---------|------|
| `Chunker` | 文本 → List[Chunk(text, metadata)] |
| `Embedder` | 文本 batch → List[vector]，封装 API 重试 |
| `Retriever` | query_vector + kb_id → Top-K chunks |
| `Generator` | context + question → LLM 调用 |
| `RAGPipeline` | 编排 ingest / query，统一入口 |
| `IngestWorker` | 异步执行 ingest，更新 document 状态 |

## 4. Prompt 模板（初版）

### System Prompt

```
你是 MindBase 知识库助手。请严格根据以下「参考资料」回答用户问题。

规则：
1. 仅使用参考资料中的信息，不要编造。
2. 若资料不足以回答，请明确说「根据现有资料无法回答」。
3. 回答中使用 [1][2] 标注引用，对应参考资料编号。
4. 回答简洁、结构化，使用中文。
```

### User Prompt 模板

```
## 参考资料
[1] （来源：{doc_title}，第{page}页）
{chunk_text_1}

[2] ...
{chunk_text_2}

## 用户问题
{question}
```

## 5. 异步任务设计

MVP 可用 **FastAPI BackgroundTasks** 或 **asyncio.create_task**；文档量大时升级为 **Celery + Redis**。

### 文档状态机

```
pending → processing → ready
                    ↘ failed (error_message)
```

前端：上传后轮询 `GET /documents/{id}` 直到 `ready` 或 `failed`。

## 6. 安全设计

| 点 | 方案 |
|----|------|
| 认证 | JWT Access Token（2h）+ Refresh Token（7d）可选 |
| 授权 | 所有资源带 `user_id`，查询必须过滤 |
| 文件 | 校验扩展名 + MIME + 大小；存储路径不可预测 |
| API Key | 仅存 `.env`，不进 Git |
| 限流 | Redis 计数：每用户每日 N 次问答 |

## 8. 部署架构

```
docker-compose.yml
├── postgres:16       # 含 pgvector 镜像
├── redis:7
├── backend           # uvicorn
└── frontend          # nginx 静态资源 或 dev proxy

生产可选：后端部署到云服务器，前端 Vercel / 同机 Nginx
```

### pgvector 初始化

```sql
CREATE EXTENSION IF NOT EXISTS vector;
-- chunk 表 embedding 列：vector(1536) 维度与 Embedding 模型一致
CREATE INDEX ON document_chunk USING hnsw (embedding vector_cosine_ops);
```
