# 01 — 项目规划

## 1. 为什么要做这个项目

### 1.1 市场与招聘背景

2025–2026 年，「LLM 应用层」是 AI 实习岗增长最快的方向之一。企业需要的不是「会调 ChatGPT 网页」，而是能落地：

- 文档 ingestion 与知识管理
- RAG（检索增强生成）pipeline 设计与调优
- Prompt 工程与幻觉控制
- 工程化：鉴权、异步任务、可观测、部署

个人知识库 + AI 问答是**业务清晰、技术栈完整、Demo 效果好**的经典 RAG 场景，面试时 3 分钟能讲透全流程。

### 1.2 与常见项目的差异

| 常见项目 | 问题 | MindBase 的差异化 |
|----------|------|-------------------|
| ChatGPT 套壳 | 无技术深度 | 完整 RAG pipeline + 引用溯源 |
| Todo / 博客 | 与 AI 岗无关 | 核心就是 AI 检索与生成 |
| 纯算法 Demo | 无工程能力 | 全栈 + 数据库 + 异步 + 部署 |
| Dify/LangChain 一键部署 | 不是自己写的 | 自研核心模块，能讲每一层 |

## 2. 产品定义

### 2.1 一句话描述

**MindBase**：用户上传私有文档，构建个人知识库，通过自然语言提问并获得**带引用来源**的 AI 回答。

### 2.2 目标用户

- 大学生：课程资料、论文、笔记问答
- 开发者：技术文档、API 文档检索
- （可扩展）小团队内部知识库

### 2.3 核心用户故事

1. 作为用户，我可以注册账号并创建多个知识库（如「操作系统」「机器学习」）。
2. 作为用户，我可以上传 PDF/Markdown，系统自动解析并建立索引。
3. 作为用户，我可以在某个知识库中提问，系统基于**我的文档**回答，并展示引用段落。
4. 作为用户，我可以查看历史对话，并删除/重新上传文档。

### 2.4 功能边界（明确不做什么）

| 不做 | 原因 |
|------|------|
| 多模态（图片/视频） | 范围过大，MVP 聚焦文本 |
| 自训练模型 | 实习岗不要求，用 API 即可 |
| 复杂 Agent 编排 | 可作为 Phase 4 扩展，MVP 不做 |
| 多人协作编辑 | 非核心，后期可选 |

## 4. 技术选型结论

| 层级 | 选型 | 理由 |
|------|------|------|
| 后端 | **FastAPI** | Python AI 生态最好，异步友好，自动 OpenAPI |
| 前端 | **React + Vite + Ant Design** | 生态成熟，管理后台组件多 |
| 关系库 | **PostgreSQL 16** | 稳定，支持 **pgvector** 扩展 |
| 向量检索 | **pgvector** | MVP 够用，部署简单，面试能讲 HNSW 索引 |
| 缓存/队列 | **Redis** | 任务状态、限流、可选 Celery broker |
| 文档解析 | **pypdf** + **markdown** | PDF/MD 够用；后期加 **unstructured** |
| Embedding | **通义 / 智谱 / OpenAI 兼容 API** | 国内可用，dimensions 固定 |
| LLM | **DeepSeek / 通义 qwen-max** | 性价比高，OpenAI 兼容接口 |
| ORM | **SQLAlchemy 2.0 + Alembic** | 迁移管理规范 |
| 部署 | **Docker Compose** | 一键启动 PG + Redis + Backend |

> 进阶可选：向量库换 **Milvus**、检索加 **Elasticsearch BM25**，作为「优化迭代」故事。

## 5. 非功能需求

| 指标 | MVP 目标 |
|------|----------|
| 单文档大小 | ≤ 20 MB |
| 解析延迟 | 10 页 PDF < 30s（异步，前端轮询状态） |
| 问答延迟 | 首 token < 3s（流式输出时） |
| 并发 | 单用户 Demo 级即可，架构预留扩展 |
| 安全 | JWT 鉴权、用户数据隔离、API Key 不入库 |

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| API 费用 | 用 DeepSeek 等低价模型；Embedding 用 batch；设每日限额 |
| PDF 解析乱码 | 限制「可选中文字」的 PDF；失败时提示用户 |
| 检索不准 | 调 chunk_size / overlap；加混合检索；记录 bad case |
| 范围蔓延 | 严格按 [05-开发里程碑.md](05-开发里程碑.md) 执行，进阶功能放 Phase 4 |
