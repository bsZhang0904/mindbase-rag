## 2. 三分钟 Demo 脚本

### 开场（20 秒）

> 这是 MindBase，一个基于 RAG 的个人知识库。用户可以上传 PDF 或 Markdown，系统会自动建索引，然后针对**私有文档**进行问答，并且每个回答都会标注引用来源，避免幻觉。

### 演示步骤（2 分钟）

1. **登录** → 展示知识库列表  
2. **打开「操作系统」知识库** → 展示已上传的 2 份 PDF  
3. **提问**：「什么是虚拟内存？它解决了什么问题？」  
4. **指向回答中的 [1][2]** → 展开右侧引用面板，展示原文段落和页码  
5. **追问边界**：「今天天气怎么样？」→ 展示「资料中无法回答」  
6. **（可选）打开 Swagger** → 展示 `/chat/stream` 接口  

### 收尾（40 秒）

> 技术上是经典 RAG 架构：pgvector 做检索，DeepSeek 做生成。我重点做了切块策略和引用溯源。如果检索不准，我还记录了 bad case，并通过调整 chunk_size 和 Top-K 做了对比实验。

## 3. 高频追问 & 参考回答

### Q1: 介绍一下你的 RAG 流程？

**答**：分两条链路。Ingestion：上传文件 → 解析成纯文本 → 按 500 字切块、50 字 overlap → 调 Embedding API 向量化 → 存 pgvector。Query：用户问题 embed → cosine 检索 Top-K → 拼 Prompt → LLM 生成 → 返回 answer + citations。

---

### Q2: 为什么用 pgvector 而不是 Milvus / Elasticsearch？

**答**：MVP 阶段数据量小（单用户千级 chunk），pgvector 与 PostgreSQL 一体，运维简单，事务和关系数据同库。面试项目要展示架构能力而不是堆组件。若 chunk 到百万级，会考虑 Milvus 专库 + 混合检索。

---

### Q3: chunk_size 怎么选的？调过哪些参数？

**答**：初始 500 字符 / overlap 50，按段落优先切。试过 800 字：上下文更全但噪声多；300 字：检索细但容易断章取义。Top-K 从 5 调到 8，在「操作系统」测试集上 Recall@5 从 XX% 到 XX%（**填你的实测**）。

---

### Q4: 怎么减少幻觉？

**答**：三层：① Prompt 约束「仅根据参考资料」；② 检索分数低于阈值时直接拒答；③ 强制引用标注，用户可点原文核对。还测了「资料外问题」拒答率。

---

### Q5: Embedding 和 LLM 为什么分开选？

**答**：Embedding 要稳定、便宜、支持 batch；LLM 要指令遵循好。我 Embedding 用通义 text-embedding-v3，LLM 用 DeepSeek，都走 OpenAI 兼容接口，方便切换。

---

### Q6: 异步文档处理怎么做的？

**答**：上传后写 document status=pending，BackgroundTasks 启动 ingest：processing → 解析 embed 写库 → ready/failed。前端轮询 GET /documents/{id}。量大可升级 Celery + Redis 队列。

---

### Q7: 如何做权限隔离？

**答**：所有表带 user_id 或通过 kb_id 关联到 user。API 层 get_current_user 注入，查询必须 filter user_id。JWT 无状态，Access Token 2 小时过期。

---

### Q8: 如果 QPS 很高怎么优化？

**答**：读路径：Redis 缓存热点 chunk、Embedding 结果缓存（相同问题）；写路径：ingest 走队列削峰。向量检索加 HNSW 参数调 ef_search。LLM 侧流式降低首字节延迟。水平扩展：无状态 API 多实例 + PG 读副本。

---

### Q9: 遇到过什么坑？

**答**（选 1–2 个真实经历，示例）：

- 扫描版 PDF 无文字层 → 解析为空 → 加检测 + 友好报错  
- Embedding 维度和 pgvector 列不一致 → 迁移脚本写死 1536  
- 中文切块按字符不按 token → 改用字符数 + 段落边界  

---

### Q10: 和 LangChain / Dify 比，你为什么自己写？

**答**：LangChain 适合快速验证，但我需要理解每层实现以便调优和面试讲解。核心 4 个类 Chunker / Embedder / Retriever / Generator 约 XXX 行，可控可测。后期可局部引入 LangChain 的 loader，但 retrieval 自研。
